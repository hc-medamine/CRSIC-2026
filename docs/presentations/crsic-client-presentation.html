Institution

Why a digital presence exists

🏛️Public scientific centre

CRSIC is a public scientific and technological research centre under Algeria’s Ministry of Higher Education and Scientific Research. Founded by executive decree 15-136 (23 May 2015); opened January 2016, Laghouat.

🎯Public channel

Present the centre, research departments, publications, journals, events, partnerships, news, and contact paths to researchers, partners, and the public.

🔐Controlled publishing

Staff publish through roles and review — not by editing live WordPress or raw production files by hand.

Transition

What changed in practice

Owned content types have already cut over. Journals remain on Open Journal Systems by design.

Before

WordPress + informal edits

  • Unclear ownership of who could change live pages
  • Risk of direct production edits without review
  • Harder to attribute who published what, when
  • Public runtime tied to a heavier CMS stack
Now

Static public site + editorial desk

  • Desks assign exclusive ownership by type / org unit
  • Draft → submit → review → manual publish
  • Author cannot approve their own item (four-eyes)
  • Visitors load static pages; desk writes approved snapshots
Cutover scope: news, events, publications, partners, research groups/projects, laws, platforms, alerts, director, featured playlist, site pages. Out of desk: journals (OJS).

Architecture

Two surfaces, one publish path

Visitors never run the editorial system. Staff never hand-edit the live public files.

🌐1 · Public website

  • Single-page shell with hash routes (#home, #news, #publications…)
  • Content from JSON files (local /data or optional CDN base URL)
  • Zero build for visitors — browser loads modules directly
  • Deployable on Vercel, Netlify, or Apache static hosting
  • Contact opens mailto:contact@crsic.dz — no public form backend
  • Soft-fail: if one JSON file fails, other sections still render

🗂️2 · Editorial desk

  • Internal Next.js app + PostgreSQL for drafts and workflow
  • On Publish: builds public object, stores live payload, rebuilds matching data/*.json
  • Unpublish clears live payload and rebuilds without that item
  • “Create revision” returns to draft while public copy stays live
  • Media published under img/cms/… (tracked for consistent clones)
  • Preview tokens for candidate payloads before go-live

Language policy

Arabic-first, English when ready

🌐Interface (chrome)

  • Default: Arabic, dir=rtl, lang=ar
  • English flips UI to LTR
  • Preference via ?lang= and localStorage
  • 350 keys in ar.json and en.json — sets must stay in sync
  • Optional banner if browser prefers EN or FR

📝Editorial bodies

  • Arabic is the publish baseline
  • EN fields (title/summary/body) show publicly only when en_status = ready
  • Per-field fallback to Arabic if EN missing
  • Desk tracks “English pending” separately from publish status
  • Journals remain Arabic / OJS-linked
Desk chrome also supports AR RTL / EN LTR via cms_lang cookie — staff can work in either direction.

Editorial desk · workflow

How an item becomes public

Statuses: draft → submitted → approved → published. Side paths: changes_requested, rejected, unpublished.

1

Draft

Editor on assigned types; Arabic required; media upload; EN optional

2

Submit

Enters review queue; withdraw possible before approval

3

Decide

Request changes / approve / reject — author cannot self-approve

4

Publish

Manual only; rebuilds public JSON; revision keeps live copy

Live-safe revision

“Create revision (public stays live)” returns a published item to draft while live_payload remains until the next publish.

Emergency path

Super Admin may emergency-publish with audit trail and post-review flag — exceptional, not routine.

Editorial desk · roles

Who can do what

Oversight

👑 Super Admin

Users, desks, org units, audit, import/export, recycle, all types. Password resets. Emergency publish.

Gate

👁️ Reviewer

Approve / request changes / reject / publish / unpublish in exclusive org scope. Cannot manage users.

Author

✏️ Editor

Create/edit own items in assigned content types only. Submit and revise. Cannot approve or publish alone.

Desks (ownership model)

  • Editors: globally exclusive content types (or per research department)
  • Reviewers: exclusive organisation claims
  • Align authorship after desk changes so Editors can open owned items

Editorial desk · capabilities

Operational tools already available

⭐ Featured playlist

Order up to 10 news ids for home spotlight. News Editor + SA + Reviewer edit draft; only Reviewer/SA publish the playlist.

🖼️ Media library

JPEG/PNG/WebP/PDF, max 5 MB, magic-byte check. Scoped by role. Cover crop / img_card for publications.

♻️ Recycle bin

Soft-delete; restore to draft. Editors: own draft/rejected. SA: unpublished/rejected. Stale after 90 days.

⧉ Clone

Duplicate → new draft (title suffix copy). From edit page and bulk for Reviewer/SA.

📦 Import / Export

SA zip of desk records + files. Export selected. Import always creates new drafts — never live.

📜 Audit & revisions

Append-only audit log. Revision history with restore to editable draft (Reviewer/SA).

🔔 Notifications

In-app only — no SMTP for alerts or password recovery.

👁️ Preview

In-form public card preview + short-lived tokens for SPA #preview/{token}.

↕️ Lists UX

Load more (20), header sort this visit, bulk unpublish/recycle with skip report.

Safeguards

Controls in force

🛡️ Access & integrity

  • Encrypted iron-session cookies; Secure in production; SameSite=lax
  • Password hashing (bcrypt); SESSION_SECRET ≥ 32 chars
  • 30-minute idle timeout with activity touch
  • Role + org + content-type checks on every action
  • Four-eyes on review/publish; deactivated users cannot log in
  • Public site: no login surface; DOM built without raw innerHTML for content

📋 Release & recovery

  • Written product decision (PRD) before feature coding
  • ~5 minute smoke checklist before merge to live line
  • Publish rebuild with .bak / temp / rename; rollback on failure
  • Recycle instead of hard delete; media DELETE blocked if still referenced
  • Import never lands as published
  • WordPress cutover for owned types already applied on main
